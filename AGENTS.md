# AGENTS.md

Repository guidance for coding agents and contributors working in this project.

## What this is

`dotimation` is a single-component React library ("Animate anything with dots"). It renders text or images as a field of animated dots on a `<canvas>`, with spring physics that morphs smoothly between layouts when the content or size changes. The public API is just `<Dotimation>` plus its types (`src/index.tsx`).

Runtime targets: React 19 + react-dom 19 (peer deps). The package ships ESM-only from `dist/`.

## Commands

Bun is the only supported toolchain (`bun.lock`, `bunfig.toml`). Do not use npm/yarn/pnpm.

- `bun install` — install deps
- `bun run dev` — start the Vite playground (`test/ui`) that imports the library **directly from `src/`** (see its `vite.config.ts` alias); no build needed to see changes
- `bun run build` — runs `scripts/build-worker.ts` first (generates the inlined worker source at `src/raster/worker-source.ts`), then bundles to `dist/` via `bunup` (minified, no sourcemaps; config is all CLI flags, no `bunup.config.ts`)
- `bun run type-check` — compile the library and unit/public-API type tests (`tsconfig.json` + `test/tsconfig.json`)
- `bun run lint` / `bun run lint:fix` — Biome check / autofix
- `bun test` — run tests; `bun test path/to/file.test.ts` for a single file; `bun test -t "name"` for a single test; `bun run test:watch`, `bun run test:coverage`
- `bun run test:e2e` — headless-Chromium smoke of the playground (`test/e2e/smoke.e2e.ts`; named `.e2e.ts` so `bun test` skips it). Boots Vite itself; needs `bunx playwright install chromium` once. Covers the DOM/GPU shells unit tests can't: backend cascade, canvas sizing/a11y, pixel output, reduced motion, and the jitter-derived loop policy (shimmer persists indefinitely while `jitter > 0`, sleeps after settle when `jitter === 0`, a live jitter change never remounts the canvas). The playground exposes `motion` as sliders (jitter/settleTime/damping/fade) alongside the dot/backend controls; its `use-config` hook also honors an e2e-only `?jitter=` query override so the suite can pin a starting value deterministically. Runs in CI as its own ubuntu job.

A `simple-git-hooks` pre-commit hook runs `lint` + `type-check`. CI (`ci.yml`) runs build → distribution validation → type-check → lint → test on Linux/macOS/Windows.

## Architecture: the particle pipeline

The library is one data flow from source content to animated pixels. There is a strict **pure-core / DOM-shell split**: pure logic (field, sampler, simulate, render, settle, params, clock) is unit-tested under `bun test`; DOM/React-bound shells (rasterize, engine, backend, component) are exercised in the `test/ui` playground.

1. **Rasterize** (`src/raster/`) — Rasterization runs in a **Web Worker** when safe: `src/raster/raster.worker.ts` (uses `OffscreenCanvas`) is bundled to a self-contained string by `scripts/build-worker.ts` → gitignored `src/raster/worker-source.ts` (regenerated on `bun install` / `bun run build` / `bun run dev`), and instantiated via a Blob URL in `src/raster/rasterize-worker.ts` — so it ships inlined and runs for any consumer regardless of bundler. The pure `isWorkerSafe` (`src/raster/worker-safe.ts`) keeps custom-font text on the main thread (workers have a separate font set); a main-thread `rasterize` fallback covers every failure. Shared draw/scale helpers live in `src/raster/draw.ts`.

   `rasterize()` (DOM shell) draws the `AnimateItem` (text or image) onto an offscreen canvas and calls the pure `sampleTargets()` (`src/raster/sample.ts`) to walk the pixel buffer on a grid (`spacing` step) and produce `FieldTargets` — a Structure-of-Arrays (SoA) of home positions and colors for every sampled pixel. Text auto-sizing lives in `src/utils/font.ts` (`AUTO` = glyph-weighted heuristic, `AUTO_MONO` = monospace blend); `resolveFontSize` (`src/raster/draw.ts`) clamps auto sizes so multiline text also fits the **height**. The `useFieldTargets` hook (`src/hooks/use-field-targets.ts`) re-rasterizes when **any** raster input changes — `item` (shallow-compared), `width`/`height`, `defaultFontFamily`, `threshold`/`spacing`/`max` (the resolved `dots` fields), or the component's DPR epoch — via the pure, unit-tested `sameRasterInputs` (`src/raster/inputs.ts`). Raster work is **coalesced** through a latest-wins scheduler (`src/utils/latest-wins.ts`: one run in flight, only the newest input queued — a drag-resize does one pixel walk, not sixty) and an `executionId` ref discards stale async results. Decoded images are cached in a small promise LRU (`src/utils/async-lru.ts`) on both paths — `HTMLImageElement`s on the main thread, `ImageBitmap`s (closed on eviction) in the worker. Empty `item.data` publishes a zero-particle layout (fade-out) rather than freezing the previous content; a failed rasterization forgets its inputs (and evicts the failed image) so the next render retries even with a referentially stable item. The scheduling effect checks each commit; `sameRasterInputs` prevents redundant successful work. The worker self-terminates after ~10 s idle (respawned on demand), times out requests, and falls back to the main thread on any failure.

2. **Field model** (`src/engine/field.ts`) — one `ParticleField` of typed Float32Arrays (Structure-of-Arrays). `reconcile(field, targets, opts?)` maps the old layout onto new targets in a single fixed-capacity buffer: slots `[0, active)` are the live layout, slots `[active, count)` are faders leaving (per-particle `targetAlpha = 0`). The buffer grows via `growField` (rounds up to next power-of-2) only when needed. `opts.matching: 'spatial'` (the `matching='nearest'` prop) pairs slots with targets by Morton rank (`src/engine/morton.ts`, pure + unit-tested) instead of by index — **ordering keys must stay home-domain** (outgoing homes for pre-existing slots, the just-written spawn position for spawn slots; never simulated x/y, which are stale under GPU tiers). `snapField(field)` completes a morph instantly (used for reduced motion); a snapped field is pushed with `setField(field, true)` so GPU tiers re-upload the whole state instead of diffing.

3. **Orchestrator** (`src/engine/engine.ts`) — owns the rAF loop, a fixed-timestep accumulator (`src/engine/clock.ts`, 90 Hz physics), and an `IntersectionObserver` for visibility gating. The loop's lifetime policy is **derived from `jitter`**: `jitter > 0` means the shimmer never converges, so the loop runs continuously while the canvas is on-screen; `jitter === 0` means the field goes still once settled, so the loop sleeps — after a per-instance budget measured in simulated time (offscreen pauses and clamped frame deltas do not consume it), computed by `computeSettleDuration(settleTime, opacityRate, colorRate)` (`src/engine/settle.ts`), or as soon as the backend reports `settled()`, whichever comes first — for ~0% idle CPU. While the loop runs it draws **every frame** (no 0-step draw skip — that skip was why webgl2 once needed `preserveDrawingBuffer`, which is now off). Exposes `setField` / `setParams` / `resize` / `dispose` and drives a `Backend` interface. `setParams(params: SimParams)` (`src/engine/params.ts`) pushes dot size, jitter, spring `k`/`c`, settle time, and fade/color rates to the backend live, re-derives the settle duration and continuous-vs-sleep policy, and — same as `resize` — never recreates anything (simulation state survives). The engine itself is recreated — with a freshly keyed canvas — when `backend`, the DPR epoch, `maxDpr`, or reduced-motion changes, or when an initialization failure requires the next fallback tier. Startup is cancellable, and both params and backend dimensions are synchronized after asynchronous initialization.

   `src/engine/params.ts` is the single source for both public options objects and their derived internals: `resolveDots`/`resolveMotion` fill defaults and sanitize `DotOptions`/`MotionOptions` silently (out-of-range input degrades to a clamp or the default, never throws — see `MIN_SETTLE_TIME`/`MIN_DAMPING` for the integrator-stability floors), and `toSimParams` is the **only** call site for `tuneSpring` (`src/engine/settle.ts`, the settle-time/damping → spring `k`/`c` conversion), so the three backend tiers cannot drift onto different spring math. There is no `constants.ts` anymore — everything it used to hold now lives here, resolved per-instance instead of module-global.

4. **Backends** (`src/backends/`) — a `Backend` implements `init / uploadField / setParams / step / draw / resize / dispose` (`settled?` optional), constructed with the full `SimParams` (`src/engine/params.ts`: dot size, jitter, spring `k`/`c`, settle time, opacity/color rates — jitter is 0 under reduced motion, forced by `toSimParams`) and re-tuned live thereafter via `setParams`. Three backends ship:
   - **`canvas2d`** (P0, `src/backends/canvas2d/`): SoA spring simulation in `simulate.ts` (whose `stepField` also returns a fused settled report, making the engine's per-frame `settled()` check O(1); `src/engine/rest.ts` owns the single per-slot predicate `isSlotSettled` shared with `isFieldSettled`) and a `Uint32`/`ImageData` pixel-push renderer in `render.ts` with hoisted endianness detection.
   - **`webgl2`** (P1, `src/backends/webgl2/`): runs the particle simulation on the GPU via **transform feedback** and renders dots as **instanced quads**. Uses the shared pure planner `src/engine/reconcile-plan.ts` (`planReconcile` → `FieldDelta`) for readback-free reconcile→GPU sync (P0's `reconcile` was refactored onto the same planner). Exercised in the playground and Chromium e2e tests, including failed initialization and context restoration.
   - **`webgpu`** (P2, `src/backends/webgpu/`): runs the particle physics in a **WGSL compute shader** over storage buffers and renders dots as **instanced quads**. `@webgpu/types` is a devDependency. Exercised in Chromium using real WebGPU pipelines and texture readback on SwiftShader; focused parity checks also pass on the available Metal adapter.

   Everything the two GPU tiers structurally share lives in `src/backends/gpu-shared.ts` — the interleaved buffer layout (`STATE_FLOATS`/`TARGET_FLOATS`/`STATE_STRIDE_BYTES`), the unit `QUAD`, the `packStateInto`/`packTargetsInto` packers (unit-tested in `test/backends/gpu-shared.test.ts`), the normalized fader-expiry threshold `FADE_COMPLETE` (backends accumulate `dt * opacityRate`, so live fade-rate changes cannot prematurely drop visible particles), and `ensureScratch` — a single source the tiers cannot drift from. `src/engine/reconcile-plan.ts` is planner-only.

   `src/engine/select.ts` starts an **async cascade**: `resolveBackendOrder` in `src/engine/cascade.ts` gives `'auto'` the supported subset of `webgpu → webgl2 → canvas2d`; an explicit request starts at that tier. GPU modules use dynamic imports. `selectBackend` initializes one tier and throws `BackendRetryError` with the next tier on failure. The component remounts a **fresh canvas** before retrying: acquiring a context permanently binds the canvas to its type, even if later initialization fails. An `AbortSignal` prevents cancelled initialization from binding the canvas or triggering fallback. If Canvas2D also fails, the component logs the terminal error. WebGPU initialization captures asynchronous validation errors and releases devices on configuration failure or late cancellation.

   **Cross-tier parity:** all three backends use premultiplied source-over blending, snap dots to the device-pixel grid, and derive the dot footprint as `max(1, round(dotSize * dpr))` — `dotSize` is **CSS px** on every tier, so dots render the same visual size at every DPR. The `max(1, …)` floor is also a contract: `dots.size: 'hairline'` resolves to `dotSize: 0` and relies on it to render exactly 1 device pixel on every tier. The per-step jitter hash on the GPU tiers is an integer PCG on `u32` (same `[0, 1)` contract as the CPU PRNG; a fresh 32-bit seed per step). Morphs are also tier-identical: `reconcile` spawns and collapse-matches from **home** positions, never live `x`/`y` — under GPU tiers the CPU field is not simulated, so its live positions are stale. Both GPU tiers recover from context/device loss (webgl2 via `webglcontextrestored`, webgpu by re-acquiring a device) and snap the last uploaded CPU field to its target and repaint immediately; CPU positions and alpha are stale under GPU simulation, so uploading them unchanged would leave a sleeping engine blank.

### Component props beyond the basics

- **`fill?: true`** — instead of `width`/`height`, the canvas is styled 100%/100% and its CSS content box is tracked with a `ResizeObserver` (props are a union: fixed size XOR fill). Until the first observation the derived size is 0 and `useFieldTargets` publishes an empty layout.
- **`dots?: DotOptions`** (`{ size?, spacing?, threshold?, max? }`) — replaces the old flat `dotSize`/`pointSpacingCss`/`alpha`/`maxParticles` props. `resolveDots` (`src/engine/params.ts`) runs every render into primitive fields (never the object itself) so downstream deps compare values, not identity: `size` feeds `SimParams.dotSize`, `threshold`/`spacing`/`max` feed `useFieldTargets` (item 1). `size` also accepts `'hairline'` — resolved to the internal `dotSize: 0` sentinel, which the cross-tier footprint floor renders as exactly 1 device pixel at any DPR (numeric `0` still falls back to the default, so the sentinel is only reachable via the string).
- **`motion?: MotionOptions`** (`{ jitter?, settleTime?, damping?, fade? }`) — likewise resolved every render via `resolveMotion`/`toSimParams` into `SimParams`; a dedicated effect keyed on the primitive fields (not object identity) pushes changes to the live engine via `engine.setParams`, never recreating it. `jitter` also drives the engine's loop policy (item 3). There is no more `idle` prop — `idle="sleep"` is `motion={{ jitter: 0 }}`; `idle="animate"` was the default and needs no replacement.
- **`matching?: 'swarm' | 'nearest'`** — particle↔target assignment on content change (see the field model); read via a ref, applies from the next reconcile.
- **`maxDpr?: number`** (default 2) — density cap; a change is a density change, so it participates in the canvas key and engine-recreation deps exactly like `dprEpoch`.
- **`reducedMotion?: boolean`** — overrides the OS media query when set (apps with their own motion setting); omitted = auto-detect.
- **`onStats?: (stats: { backend: 'webgpu' | 'webgl2' | 'canvas2d'; particles: number }) => void`** — fires on engine creation and each field update; exposes the resolved backend (useful to see which tier `'auto'` chose) and the live particle count.
- **`ref?: React.Ref<HTMLCanvasElement>`** — React 19 ref-as-prop to the underlying canvas. `canvasRef` is gone (no deprecated alias) — pass `ref` instead.
- **`ariaLabel?: string`** — accessible name for the canvas (rendered with `role="img"`); defaults to `item.data` for text items.

### Reduced motion

The component watches `prefers-reduced-motion` (`src/hooks/use-reduced-motion.ts`, `useSyncExternalStore`); the `reducedMotion` prop overrides it when set. When reduced: `toSimParams` forces `jitter: 0` in the `SimParams` given to the backend regardless of the `motion` prop (no shimmer, and the engine's loop sleeps after settle instead of running continuously), and every morph is completed instantly via `snapField` + a full-state upload — content changes appear immediately at the target with no movement or fade. A live flip re-keys the canvas and recreates the engine.

### Web fonts

`useFontEpoch` (`src/hooks/use-font-epoch.ts`) bumps a raster input once when a custom (non-generic) font family finishes loading, so text first rasterized with fallback metrics is re-rasterized with the real ones. `isGenericFamily` (`src/raster/worker-safe.ts`, pure) decides what counts as custom; `document.fonts.check` and `load` receive the actual text so unicode-range font subsets load correctly; the check short-circuits already-loaded fonts and a `load()` resolving with no faces (no matching `@font-face`) does NOT bump.

### Coordinate systems & DPR

Particle positions are in **CSS pixels**; the canvas backing store is **device pixels** (`width * dpr`). `dpr` is `min(devicePixelRatio, maxDpr)` — the cap defaults to 2 and is single-sourced through `getDpr(max?)` (`src/utils/utils.ts`); `sizeCanvas`/`getCtx`/`rasterize` take the resolved dpr as an explicit parameter. The component sizes the canvas backing store exclusively in one pre-paint layout effect (`useIsomorphicLayoutEffect` — plain `useLayoutEffect` warns under SSR) via `sizeCanvas` — a context-less, **idempotent** helper (assigning `canvas.width` even to the same value clears the canvas, so every write is guarded). The JSX carries no `width`/`height` **attributes** (React re-committing them in CSS px would clear/resize the canvas wrongly on every change) but does declare the CSS box in `style`, so server-rendered HTML reserves the right space. The engine passes `dpr` to the backend at `init`; the backend handles device-pixel conversion internally. `devicePixelRatio` **changes** (browser zoom, monitor move) are watched via a re-armed `matchMedia` resolution query; each change bumps a `dprEpoch` that remounts the canvas and recreates the engine at the new density.

## Conventions & gotchas

- **`isolatedDeclarations: true`** (tsconfig) — every exported function/component needs an explicit return type. This is why `Dotimation` is annotated `: React.ReactNode` and helpers declare return types. Add them when exporting new symbols or type-check fails.
- **`noUncheckedIndexedAccess: true`** — array/object index access is `T | undefined`. The `!` non-null assertions throughout (`arr[i]!`) are deliberate and Biome's `noNonNullAssertion` is turned off to allow them.
- **Path alias `@/*` → `src/*`** exists but is used inconsistently (`index.tsx` uses `@/...`, most files use relative imports). Match the file you're editing.
- **Formatting** is Biome-owned: single quotes, no semicolons (`asNeeded`), 2-space indent. `.editorconfig` uses the same two-space indentation; let `bun run lint:fix` format.
- **Unit tests** live under `bun test` and cover the pure cores (field, sampler, simulate, render, settle, params, rest, clock, prng, raster-inputs, cascade, reconcile-plan, gpu-shared packers, morton/spatial matching, font sizing, latest-wins, async-lru). `test/engine/params.test.ts` covers `resolveDots`/`resolveMotion` sanitization and `toSimParams`. DOM/React-bound code (rasterize, engine, backends, component) is covered by the e2e smoke suite (`bun run test:e2e`) and the `test/ui` playground.
- **Shared PRNG** (`src/utils/prng.ts`): the hot paths use a seeded xorshift32 with a strict **[0, 1)** contract (divide by 2^32, never by 0xffffffff — closed-range rand once indexed out of bounds in `sampleTargets`).
- **Do NOT add `"sideEffects": false` to package.json** — bunup's tree-shaking then strips the entire library and emits a dangling `export{m as Dotimation}` (44-byte broken bundle). Verified 2026-07: check `dist/index.js` size if you touch bundler config.
- **Never build with bare `bunup`** — without the `build` script's flags it defaults to `--target node` and emits a `createRequire`/`node:module` shim into a shared chunk, which breaks every browser bundler that consumes the package (shipped broken as v0.7.0). `prepublishOnly` rebuilds via `bun run build` and runs `scripts/check-dist.ts` (asserts the footer is present and no `node:`/`bun:` builtins appear in `dist/`), so a stale or wrongly-built `dist/` can no longer be published.


## Regression rules for expansion

- `sizeCanvas` writes only backing-store dimensions. React owns CSS width/height; writing pixel styles breaks `fill`. Zero-size canvases are valid while hidden or before measurement; do not allocate zero-size ImageData or present zero-size WebGPU textures.
- Animation settle budgets cover position, opacity, and worst-case color convergence. Engine budgets advance with physics steps, not wall-clock time. Before sleeping, snap the authoritative targets and upload the full state so an approximate spring deadline cannot leave a morph short. GPU fader expiry integrates opacity loss across the actual rates used.
- Raster job cleanup invalidates pending/queued results. Failed image loads may evict only their own promise, never a replacement request for the same URL. Worker construction failures still revoke Blob URLs; postMessage failures remove pending requests; timeouts terminate the failed worker. Resolve relative image URLs against document.baseURI before posting to a Blob worker.
- Clamp Canvas2D footprint loops to visible bounds before iterating; use floor(x * dpr + 0.5) on all tiers, including negative positions. GPU random values use 24 hash bits to preserve [0, 1) after f32 conversion.
- Public type assertions are enforced by `test/tsconfig.json`; do not remove it from the type-check command. CI validates built output with `scripts/check-dist.ts`.
- `test/ui/lifecycle.html` is a development-only browser test fixture. The e2e suite exercises actual fill sizing, zero-size recovery, StrictMode, failed GPU initialization, WebGL restoration, resize during delayed initialization, retry after failed image decode with stable inputs, and real WebGL/WebGPU render/compute parity. The startup race test substitutes a delayed backend; the separate GPU parity test uses actual GPU APIs and readback. `DOTIMATION_E2E_GPU_ONLY=1 bun run test:e2e` runs only parity checks; `DOTIMATION_E2E_ANGLE=metal` selects the Metal adapter on a supported host (default is SwiftShader).
- Historical plans in `docs/superpowers/` describe past implementations and may mention the former guidance filename. Follow this file and current code for present behavior. See `docs/code-review-2026-09-19.md` for the hardening review and validation limits.
